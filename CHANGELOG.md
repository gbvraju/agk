# Changelog

The changes to the kit of this repository, newest first. In flow mode a build pull request adds one line under `## Unreleased`; a release pull request moves the lines under the new version (SPEC-0028). The history before 0.54.0 is in the git log and in `docs/runs/`.

## Unreleased

## 0.59.0 (2026-10-30)

- #307 proof can run one command per test area, with only the pull request's own test files of that area: an optional `[proof]` table in `agk.toml` (`dirs`, `patterns`, `command` with `{files}`, optional `cwd`); the line names each area not proven and `--json` lists each area with its files, outcome and seconds; without the table nothing changes (brief #305, ADR-0172)
- #308 the conductor's review pass is a kit command: `session.py review-queue` prints, read-only, the pull requests that need a verdict and why (`agk:review`, a newer or edited `Question:`, `Report:`, `Correction:` or `Maintainer answer:`, a new head, green checks under a stale `agk:ci-running`; never twice on one head), `--fingerprint` lets a loop wake only on a change, `/agk:review-pass` is the conductor's prompt for one pass, and the guide documents the loop for bash and PowerShell with its guard check first (brief #306, ADR-0173)
- #310 the router never drops a wake when events arrive together: its concurrency group is per pull request (its number for all of its events, `workflow_run` included through the run's pull request; the head of a run with none, the branch for `push`), so another pull request's event no longer cancels a pending wake, and each run woken by finished checks relabels every pull request still at `agk:ci-running` whose required checks have all finished, writing only labels; `init.py` and `upgrade.py` install the new group and keep a project's `workflows:` line (brief #309, ADR-0174)
- #311 a conductor session reviews on its own cadence: its role gains the self-wake tool that `/loop` uses (`ScheduleWakeup`) and the cadence (every 10 minutes by default, nothing posted while the queue's fingerprint is unchanged, an end after two empty passes), and its guard allows exactly `session.py review-queue [--all | --fingerprint]` and `session.py queue --role conductor` of the project's own script, every other limit unchanged; a comment whose body file is not an absolute path is refused naming the likely cause (brief #284, ADR-0175)
- #312 once a stack option is accepted, `engines.py stack-next-steps` and `playbook.py next-steps` offer the default local-profile requirement as a ready-to-run `/agk:spec` sentence from `kit/templates/local-profile.md`, filled in with the option's new optional `External services:` segment; a maintainer declines it with one Residual line `local profile: declined, <reason> (YYYY-MM-DD)`, `stack-check` prints `local profile: not decided` until it is decided, and the stack ADR template gains the `local profile` practice (brief #267, ADR-0176)
- #313 the weekly drift audit can run two optional commands of the project, `unused_code` and `coverage` in `agk.toml` (empty by default; the kit installs no tool): finding D9 lists the unused-code lines (up to 20 and the count) and the covered percentage with its change since the previous audit, never blocking, and reads `unknown`, never zero, for a command that fails, runs too long or prints nothing readable (SPEC-0004 rule 25, brief #244 build b, ADR-0177)
- #314 a brief is closed when the pull request that finishes it merges: a body may carry `Finishes: #n` beside `Brief: #n` (the pull request body check accepts it only for the same number), the router wakes on a merged pull request and closes that brief as completed with a comment naming the merge commit, the builder prompt and session rule 28 tell the last build to use it, and the doctor's `brief-finished` warning lists open briefs whose pull requests all merged more than a day ago (brief #302, ADR-0178)

## 0.58.0 (2026-10-29)

- #293 the router wakes when each required check finishes, not only `governance` and `proof`: `upgrade.py` and `init.py` write the `workflows:` list of `workflow_run` in `agk-route.yml` from `required_checks` and the project's workflows and keep names a project added to it, and `doctor.py` warns (`router-wake`) when a workflow that holds a required check is not in that list (brief #285, ADR-0165)
- #294 every command whose work ends in a pull request prints its body as a file path and its text, only after the repository's own `check_pr_body.py` passed it (`--brief N|none` or `--issues FILE` give the state; the Summary is cut to 120 characters at a word boundary): `playbook.py next-steps`, `intake.py next-steps`, the new `engines.py stack-next-steps` and `design-next-steps`, and `upgrade.py TARGET --next-steps`; after an intake's approving commit `next-steps` prints the one `Approve: <full head ID> SPEC-nnnn` line; `check_pr_body.py` accepts `Brief: none (design)` and `Brief: none (spec)` for a change of `docs/design/`, or of `docs/specs/` and `docs/requirements.md`, with at most `docs/adr/`, `docs/runs/proposed-spec-amendments-*.md` and `docs/runs/decisions-log.md` beside it (brief #273, ADR-0168)
- #297 a pull request's `Depends-on: #n` passes `check_pr_mode` rule 5 when #n is a merged pull request or a brief issue closed as completed; an open issue, an issue closed as not planned or for another reason, and an unmerged pull request each fail with their own message, and the governance workflow reads each named number from the issues endpoint (brief #282, ADR-0166)
- #299 the secret scan restores the pinned gitleaks archive from the Actions cache, keyed on its version and digest and checked on every use, and a failed download prints one plain line, `could not download the secret scanner from GitHub (HTTP <code>); re-run the job`, and fails, never skips (brief #275, ADR-0171)
- #300 proof ends a timed-out test run with every process it started on Windows too (`taskkill /T /F`, no `os.killpg`), and its line reads `proof: unknown (timeout after N s, setting: proof_timeout)`; the `--json` reason stays `timeout` (brief #290, ADR-0167)
- #301 a project's conductor files the briefs it writes: its guard allows one issue creation in the checkout's own origin repository, labelled `agk-brief` alone, from a scratch file that `check_brief.py` accepts, and nothing else; the role file says to file in dependency order and to stop when a number differs, and the last pull request of a brief carries `Closes #<brief>` (brief #276, ADR-0170)

## 0.57.2 (2026-10-29)

- #268 install and upgrade on Windows: `upgrade.py`, `init.py`, `adopt.py` and `doctor.py` compare the kit's files ignoring CRLF and LF and write them with LF, and the installed `.gitattributes` pins `text eol=lf` for every path the kit installs; `init.py` refuses when the plugin's kit files are not those of the release row of its version and says where the plugin's `ref` is set (`--unreleased` installs a checkout between releases, for the kit's own tests); an invalid `config/reviewers.yaml` names the key and the reason, as for a top-level key indented under `teams:`; every kit script reads and writes text, `git` and `gh` output and standard input as UTF-8, whatever the platform default (brief #263 build c, ADR-0160)
- #271 kit scripts: every script under `scripts/agk/` that imports another kit script puts its own folder first on the import path, by its resolved location, so it runs under `python3 -I` (isolated mode), the only Python form the conductor guard allows (brief #270, ADR-0161)
- #279 a stack ADR is accepted in one plain step: one ordinary commit sets `Status: Accepted` and `Chosen: Option <X> — <one-line reason>` together and `engines.py stack-check` accepts it; `/agk:stack` ends by printing the prompt for that change and its pull request body; `check_final_clearance.py` says a stack's Chosen line is set by an ordinary commit, not a Final commit, when a Final commit changes it (brief #274, ADR-0163)
- #280 a project's own `.gitignore` lines survive every upgrade: the kit's lines sit in a marked block (`# >>> agk` to `# <<< agk`), `upgrade.py` and `doctor.py` compare and replace only the block and report the lines outside it once as "project lines kept: n", and an upgrade migrates a file that has the installed release's kit lines followed by the project's own lines instead of refusing (brief #269, ADR-0164)
- #281 governance: the run for an edited description never takes a cancelled full run of the head for the latest while another full run of it was not cancelled, and full runs created in the same second are ordered by run id, so a green head is no longer read as red (brief #272, ADR-0162)

## 0.56.0 (2026-10-26)

- #225 a person approves a spec with one short line, `Approve: SPEC-<n>`, with no commit id: the text approved is the spec as of the comment (the server-side time of the pull request's workflow runs gives the push), and the approval stops counting if a later commit changes the spec apart from its status line; an approving GitHub review counts at its own commit; the conductor's `Approval:` line shows the line to paste (REQ-039, build (g) of SPEC-0032, ADR-0132)
- #226 every pull request body that is not a draft needs one Summary line of 1 to 120 characters, the pull request template asks for it, and a project that upgrades must add the line to its pull request bodies (an open pull request needs only a description edit), and the conductor and the session rules say so (SPEC-0036 rules 1 and 6, REQ-043 build a)
- #227 router: `route.py` writes `pipeline.json` after every routing run (what waits for a person: ready, approve, counts), `kit/pipeline-schema.json` defines schema 1, and `agk-route.yml` uploads it as the artifact `agk-pipeline` for 7 days (SPEC-0036 rules 2 to 5 and 7, brief #213 build (b))
- #228 the weekly report gains the shadow review's catch rate and counts next to the conductor's verdicts, report schema 7: the item `week-totals` carries `shadow` (the counts of the week and in total with the rate, `not-running`, or `unknown`); `facts.json` carries the optional section `shadow` (REQ-042 build (c), SPEC-0035 rule 5)
- #230 the router judges the checks of a head by the latest run of each check name and the latest status of each context, so a cancelled or replaced run never makes a green pull request look red (SPEC-0032 rules 2 and 7, REQ-039, brief 229)
- #232 an edited pull request description cures a full governance run that failed only in the steps that read the body, without a new push (brief 216 build b)
- #233 router: `required_checks` in `agk.toml` (default `["proof", "governance"]`) names the checks the router judges for a pull request and the default branch; an unlisted failing check never labels a pull request red (SPEC-0032 rules 2 and 7, brief #231)
- #235 governance skips its lint, tests and installs on a status-only final commit whose base has not moved, by the same decision as proof (brief 216 build c)
- #239 the Summary check of a pull request body says whether the line is missing, repeated (how many), empty or too long (how many characters against the limit) (SPEC-0036 rule 1, brief 237)
- #240 kit: the root `pyproject.toml` the kit installs now installs as nothing (`[build-system]` and `[tool.setuptools] packages = []`), so a host that runs `pip install .` at the root no longer fails the deploy, and `agk upgrade` appends the two tables to an init install that lacks them (brief #236)

- #243 approvals: `agent_apps` in `agk.toml` (default `["claude"]`): a comment posted through a listed GitHub App never counts as a person's approval, and while the list is not empty a review does not count either; the router answers each once with `Correction needed:` (SPEC-0032 rule 5, brief #242)
