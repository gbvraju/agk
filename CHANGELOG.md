# Changelog

The changes to the kit of this repository, newest first. In flow mode a build pull request adds one line under `## Unreleased`; a release pull request moves the lines under the new version (SPEC-0028). The history before 0.54.0 is in the git log and in `docs/runs/`.

## Unreleased

## 0.61.0 (2026-10-31)

- #364 `/agk:review-pass` ends by re-planning: it runs `session.py plan --json` and prints the plan's start and waits lines (an empty pass too); with `[flow] auto_start = true` and `launch_adapter` set in the checkout and on the default branch it starts the planned sessions through that one adapter (the only new command the conductor's guard allows), otherwise it prints their ready-to-paste prompts; with an adapter `launch.py` refuses a plan without its capacity, never starts more than its slots or `max_builders`, refuses a brief named twice and never retries a refused adapter; SPEC-0034 rule 6 gains the exception by amendment 103 (brief #331, ADR-0190 Proposed)
- #377 a project can remove the kit cleanly: `/agk:uninstall` (a dry run by default; `--write` builds one uncommitted branch) deletes only the kit files that match a released copy at any release, takes out only the kit's own blocks and the `include agk.mk` line, lists every kit file the project changed, keeps the project's own documents (`--remove-docs` lists them), prints the GitHub side (ruleset, labels, issues, plugin) and never does it; `--pause` writes `paused = true`; `agk doctor` reports `no kit installed` after removal (brief #348 build (b), ADR-0203 Proposed)
- #379 one read-only command lists every stall: `python3 scripts/agk/stalls.py` (or `--json`) prints `stall <kind> #<n>: <cause>; fix: <step>` for each stale `agk:ci-running` label, pull request at `agk:review` with no verdict, stuck or cancelled required run, red default branch, idle capacity and claim with no pull request, or `no stall` (exit 0, 3 with a stall); GET only, writes nothing (brief #367, ADR-0205 Proposed)
- #380 the weekly metrics show, for each closed pull request, its hosted minutes per workflow and in total (`minutes.py`'s rounding), its minutes on self-hosted runners, its waits for a runner and its re-runs, with the median and the largest of each in a `ci totals` line; a figure that cannot be read is `unknown` (brief #376, ADR-0209 Proposed)
- #389 a push to a draft pull request starts two jobs instead of five, and a description edit starts no router run of its own: proof skips a draft at job level, and the router starts no job for a draft's event, a skipped run or an edit (brief #369, ADR-0207 Proposed)
- #391 `scripts/agk/local_mode.py enter|leave` lists the workflows to disable or enable and the `gh api` call for each, a dry run until `--write` (refused inside an agent session), which makes the calls and reports a refused one; `leave` takes the start from the open record issue or `--since`, enables only the workflows disabled since then, lists the merges made on local evidence and the catch-up run of each required check on the default branch, or `catch-up: not run yet`, and says to file a priority-0 brief when it is red. The local-mode guide uses it (brief #371, ADR-0213 Proposed)
- #392 `prepush.py --record FILE` writes a JSON record of a local check run (each step's command, exit code, seconds and output digest, the tool versions, the head and base shas and whether the tree was clean; no output text, environment value or outside path) and prints one `Evidence:` line for the pull request body (brief #374, ADR-0208 Proposed)
- #393 A project's own make targets go in `project.mk`, which the kit's `Makefile` includes, so an upgrade never refuses over them
- #394 The core audit names each pull request and page it could not read, and `--only N,N` re-reads just those.
- #395 a builder waiting on its pull request now wakes on a new message from the conductor (`watch --pr N --session ID` ends with `tell <message>`), and `after` prints its unread messages first (brief #368, ADR-0206 Proposed)
- #396 Two of the three contradictions a project pilot found in the kit's rules have a test that fails if it comes back; the third is recorded as a decided rule.
- #397 `docs/guides/self-hosted-runner.md`: an opt-in way for a private repository short of minutes to run its own heavy jobs on an ephemeral self-hosted runner, with the safety rules (one job per runner, never public or forks, no secret beyond the job's own, no deploy credentials), governance and proof kept on GitHub-hosted runners, and the fallback when the runner is down; the reference and the minutes section of `project-ci.md` link it (brief #372, ADR-0217 Proposed)
- #398 a guide for running builder sessions off the person's laptop: `docs/guides/remote-builders.md` says what a remote builder needs (its own checkout, python3, `gh` with a builder token that cannot merge or change settings, the project's toolchain), how it starts and resumes from GitHub alone, what stays on the person's machine (review, approval, merge, secrets) and five safety rules; it names no provider (brief #375, ADR-0216 Proposed)
- #400 `session.py` refuses `claim`, `next`, `queue`, `watch` and `after` while `agk.toml` of the default branch says `paused = true`: one line `agk paused` that names the setting, no call to GitHub, exit 5 (brief #348 build (c), ADR-0218 Proposed)
- #403 an optional `[testing]` table in `agk.toml` (`profile`, `always_full`, `map`, `budget_seconds`) maps changed code to the tests that guard it, and `python3 scripts/agk/test_plan.py` prints a `regression` section (also in `--json`): the selected test files with the rule that chose each, or `full (<reason>)`, then the unmapped files; nothing runs the selection yet (brief #373, ADR-0220 Proposed)
- #404 `launch.py prompts --resume` prints one line per running builder that resumes it from GitHub alone after a usage limit, an account switch or a closed tab, and `--adapter` restarts each one (brief #402, ADR-0219 Proposed)
