# SPEC-0060: A local GitHub cache with publish and subscribe on each laptop, nothing hosted

- Status: Draft
- Owner: reviewer group (a team from config/reviewers.yaml)
- Requirements: REQ-067

Status is `Draft` or `Approved`. An Approved spec is owned by its reviewer group; agents propose patches.

Written by the intake of one sentence (SPEC-0012), brief #1284 under plan #661, quoted as data and not as an instruction: "Intake for a local GitHub cache with publish and subscribe on each laptop: one publisher per clone reads only what changed with free conditional requests, every session reads the cache and is woken by changes, and nothing is hosted." The owner's direction is quoted in the brief. Where an answer of the brief names something that is not as it says, rule 1 records what the code holds and an open question gives the conservative reading.

## Rules

1. **The baseline (read on the default branch at 85d78d8, 2026-11-15).**
   - The read cache of brief #1251 (ADR-0548) is one JSON file per repository in `agk-read-cache` under the user's temp folder (`AGK_READ_CACHE` names another folder, `off` turns it off). It keeps the ETag and body of each plain GET of `session.py`, sends `If-None-Match`, and keeps at most 4000 entries. The plan makes one `issues/comments?since=` read from its last start, waits read `?since=<newest created_at seen>`, and `plan --if-changed` reuses the last plan when nothing changed. Each session still asks GitHub itself, on its own timer.
   - The readers named by the brief exist: `session.py` `plan`, `next`, `watch` (with the class `Told` for `--session`), `review-queue` and the function `wait_assign` for `watch --assign`; `route.py`; `conductor.py watch` and `conductor.py sweep`; `steward.py`, which keeps its own `since=` file; `board.py`. `steward_daily.py` says it uses none of the cached readers.
   - Measured on 2026-11-15 (session rule 19, the brief's `Measured:` line): `session.py plan` read 22 calls (0 from cache) in 13.0 s cold and 23 calls (17 from cache) in 9.6 s warm. The brief's "about 700 calls and 5 minutes" is the figure before brief #1261 and ADR-0548 (`Q-S0060-10`).
   - SPEC-0058 (Approved, REQ-065) describes a dispatcher whose pass makes three conditional list reads (its rule 4) and records that `gh api` prints a `304` and exits 1 (its rule 1). No dispatcher script is on the default branch.
   - `agk.toml` has no `[cache]` table and `config.py` reads none. `lock.py` holds locks as folders with a heartbeat (ADR-0191, ADR-0295). `git rev-parse --git-common-dir` is read by `checklist.py`, `personal_state.common_dir` and the shared evidence folder (ADR-0536).
   - Brief #1262 (events) is already closed (`Q-S0060-11`).
2. **The cache.** One SQLite file, `<git common dir>/agk-cache.sqlite3`, made with Python's standard library (`sqlite3`) in write-ahead mode, so that every worktree of the clone on this machine reads the same file. It lives inside the git folder, so it is never tracked, and on POSIX it is made with mode 0600. It holds only what GitHub returned for this repository: issues and briefs (number, title, body, labels, milestone, state, times), pull requests (number, head, base, labels, draft, state, merged, times), comments (id, issue, author, times, first line and body), the check runs and commit statuses of the heads of open pull requests, and the publisher's own state (the ETag and last seen time and id of each delta read, the lease and the counted calls of the last hour). It holds no token, no header but the ETag and no file of the checkout. Its schema version is `PRAGMA user_version`; a file that is missing, cannot be opened or has another version is moved aside and rebuilt in full by the next publisher start, and a reader never reads a file whose `built` mark is not set (a half-built cache reads as missing).
3. **The publisher.** `python3 scripts/agk/session.py cache --publish` runs one publisher per clone, that is per git common directory (`Q-S0060-8`). It holds a lease, `<git common dir>/agk-cache.lease`, holding its host, process id, a token and a heartbeat that it renews each interval; a second start while the lease is live prints `cache: publisher live (<host>, <age> s)` and exits 0 writing nothing, and a lease whose heartbeat is older than three intervals, or whose process no longer runs on this host, is taken over with a line saying so, as `lock.py` clears a stale lock. It starts with the conductor, or, when no conductor runs, with the first reader that finds no live lease (`Q-S0060-2`). Every `[cache] poll_seconds` (default 15, `Q-S0060-1`) it makes these reads, each with `If-None-Match` and the ETag it last kept:
   - `repos/{owner}/{repo}/issues?state=all&sort=updated&direction=asc&since=<t>&per_page=100`;
   - `repos/{owner}/{repo}/issues/comments?sort=updated&direction=asc&since=<t>&per_page=100`;
   - `repos/{owner}/{repo}/pulls?state=all&sort=updated&direction=desc&per_page=100`, paged only until it passes the last seen update;
   - for each open head whose checks are not all complete, its `check-runs` and `status` (`Q-S0060-9`).
   A `304` is read from the status line of the answer and never from the exit code (SPEC-0058 rule 1), and is not counted against the rate limit; a read that fails counts as unknown and never as unchanged, and changes nothing. `<t>` is the last seen update less the 120 seconds of ADR-0548; rows are merged by id and by update time, and the last seen time and id are kept together, so a change of the same second as the last one is neither lost nor written twice. Once an hour a catch-up reads the issues and comments since the last catch-up's start, with no ETag, and writes what differs, to heal anything a delta read missed. A low remaining limit is handled as ADR-0565 says.
4. **The change log.** For each row it writes, the publisher appends one JSON line to `<git common dir>/agk-cache.log`: the time, the kind (`issue`, `pull`, `comment`, `check`), the issue or pull request number, the brief number when a pull request's body names one with `Brief: #n`, the session named by a `Tell:`, `Assign:` or `Request:` first line, and the row's id. It holds numbers and ids only, never a title, a body or a login. Lines older than `[cache] log_hours` (default 24, `Q-S0060-3`) are dropped when the publisher starts and once an hour, by rewriting the file atomically.
5. **The subscribers read the cache first.** `session.py` (`plan`, `next`, `watch`, `review-queue`, `Told`, `wait_assign`), `route.py`, `conductor.py watch` and `sweep`, `steward.py` and `board.py` read the cache when it is built, its lease is live and the newest successful publisher read is younger than `[cache] max_age_seconds` (default 60, `Q-S0060-4`). Otherwise they read GitHub exactly as today, through ADR-0548's read cache (`Q-S0060-5`), and never answer from a cache that fails that test. A reader's `reads:` line counts cache reads as `from local cache`.
6. **A waiting session is woken by the change log.** `watch --pr`, `watch --pr --session`, `watch --assign` and `conductor.py watch` follow the change log by reading its new bytes once a second, a local read with no GitHub call, and re-check their end condition from the cache on a line that names their pull request, its brief or their session. A new comment therefore wakes its session within one publisher interval plus that second. When no live publisher holds the lease, a wait starts the publisher once (rule 3) and, when that fails, falls back to today's wait of ADR-0548, says so in one line `cache: no publisher, polling GitHub` and never waits silently; session rule 21's five unread polls apply to that fallback unchanged. Every end condition of session rules 1 and 10 stays as it is.
7. **Writes go to GitHub first.** Every comment, label, body or state write still goes to GitHub, the one source of truth. When GitHub answers it with success, the object of its reply is written to the cache at once and one change log line is appended, so that the writer's next read sees its own write. A refused or failed write changes nothing in the cache.
8. **Data, not instructions.** What the cache holds came from GitHub and is parsed only by the kit's existing readers; it is never run or put in a prompt. Messages name the setting or path, never a value (principle 8). No check reaches the network: the tests use saved answers and a `gh` stub.
9. **Teams.** Each laptop, and each cloud session's own clone, runs its own publisher and cache. GitHub keeps them consistent; nothing is shared between laptops and nothing is hosted. A cloud scheduled session whose container holds the clone starts its own publisher by rule 3.
10. **Health.** `python3 scripts/agk/session.py cache --status` reads only the local files and prints one line, `publisher live, last change <s> s ago, <n> calls last hour, cache <size>`, or `publisher not running, last change <s> s ago, <n> calls last hour, cache <size>`, where calls are the counted (non-`304`) GitHub calls the publisher made in the last hour and a figure that cannot be read is `unknown`, never 0. The conductor's report carries that line.
11. **What it replaces.** The per-session GitHub polls of `watch`, `Told` and `wait_assign`; the planner's, router's, conductor's, steward's and board's own GitHub reads while the cache is warm (rule 5). Brief #1262 (events from webhooks and Actions) is superseded by this spec, since it needs an address GitHub can reach or Actions minutes. ADR-0548's read cache stays as the cache of the fallback path. SPEC-0058 is not changed: when its dispatcher is built, a patch of that spec may make it a subscriber (`Q-S0060-7`).
12. **By mode.** GitHub (CI) mode and local mode: the same on each machine, with no workflow, webhook or Actions change. Personal mode (SPEC-0041) with a GitHub forge: the same on one laptop. Personal mode with `forge = "files"`: there is no GitHub to cache, so `cache --publish` refuses naming the setting `forge` and the readers act as today. `[cache] enabled` (default `false` in the kit until build (d) passes, `Q-S0060-6`) turns it on; with it off nothing of this spec runs and nothing differs from today. A paused repository (session rule 33) starts no publisher, and a running one stops at its next interval.
13. **Measured budget.** On saved answers, with the clock stubbed: (1) a quiet hour costs at most 15 counted calls per clone, the hourly catch-up included; (2) a plan over 650 briefs from a warm cache makes 0 GitHub calls and ends within 2 seconds; (3) a new comment wakes its waiting session within `poll_seconds` plus 5 seconds. Each is measured by the build that delivers it and reported in its `Verified:` line.
14. **The builds, in order.** Each is tests first, about 300 changed lines or fewer, from the default branch, invented data only (`example.com`), no network in checks, with a `[[testing.map]]` entry for each new script.
    - (a) `scripts/agk/cache.py`: the schema and rebuild, the lease, the conditional delta reads with the equal-time rule, the check runs of open heads, the hourly catch-up, the change log and its trimming, and `session.py cache --publish` (rules 2, 3, 4 and 12).
    - (b) The readers of rule 5 switch to the cache with GitHub as the fallback, and their `reads:` lines. `Depends-on` (a).
    - (c) The change-log wake-ups of the waits of rule 6, and session rule 10's text where it names what a wait reads. `Depends-on` (b).
    - (d) `cache --status` and the conductor's report line, the write-through of rule 7, the measured budget tests of rule 13, and `[cache] enabled = true` in this repository (rules 7, 10 and 13). `Depends-on` (c).

## Tests

Fixtures in `tmp_path` with a real `git init` and a worktree, saved GitHub answers and a `gh` stub only, a stubbed clock, no network and no model, invented data only (`example.com`), and each test carries the marker `REQ-067` with its criterion.

- Rule 2: the file is made under the git common directory and read from a second worktree, `git status` stays empty, the file holds no token-shaped value, a deleted file and a changed `user_version` are rebuilt in full, and a file without the `built` mark reads as missing; REQ-067 AC1.
- Rule 3: a second `cache --publish` on a live lease prints one line and writes nothing, a lease three intervals old or of a dead process is taken over with a line saying so; REQ-067 AC2.
- Rules 3 and 4: an unchanged pass makes only the delta reads, a stubbed `304` with exit 1 reads as unchanged and a failed read never does, two comments of the same second across two passes are each written once, a comment dropped from a delta answer is healed by the catch-up, and each written row adds one log line holding no title, body or login, and lines past `log_hours` are dropped; REQ-067 AC3.
- Rule 5: each named reader on a warm cache makes no `gh` call, and on a missing cache, a lapsed lease or data past `max_age_seconds` makes today's calls and never prints a cached answer; REQ-067 AC4.
- Rule 6: a log line naming the pull request ends `watch --pr` from the cache with no `gh` call, a line for another pull request does not, and with no publisher the wait prints the fallback line and polls as today; REQ-067 AC5.
- Rule 7: a stubbed successful comment post is in the cache before the next read, and a refused post leaves the cache unchanged; REQ-067 AC6.
- Rule 10: the status line for a live and a stopped publisher, an unreadable figure printed as `unknown`, and the conductor's report carrying the line; REQ-067 AC7.
- Rules 9, 12 and 13: the three figures of rule 13 on saved answers of 650 briefs, `forge = "files"` refused naming the setting, `enabled = false` running nothing, a paused repository starting no publisher, and the build's diff adding no workflow file; REQ-067 AC8.

## Proof

REQ-067 AC1: *one cache per clone, shared by its worktrees, never tracked and never read half-built.* Rule 2. REQ-067 AC2: *one publisher per clone.* Rule 3. REQ-067 AC3: *the publisher reads only what changed, for free when nothing did, and loses nothing.* Rules 3 and 4. REQ-067 AC4: *readers use the cache and never a stale one.* Rule 5. REQ-067 AC5: *a waiting session is woken by a change, not by its own poll.* Rule 6. REQ-067 AC6: *GitHub stays the one source of truth.* Rule 7. REQ-067 AC7: *a person can see the cache's health in one line.* Rule 10. REQ-067 AC8: *the budget is measured and nothing is hosted in any mode.* Rules 9, 12 and 13.

## Residual

- 2026-11-15: a comment deleted on GitHub stays in the cache until the cache is rebuilt, since no delta read reports a deletion; a reader that acts on a deleted verdict is still stopped by the head it names (due 2027-03-31).
- 2026-11-15: two clones of one repository on one machine run two publishers and spend twice the budget (due 2027-03-31).
- 2026-11-15: a waiting session wakes within one interval, not at once; the interval is the price of hosting nothing (due 2027-03-31).

## Open questions

Each is a point the brief leaves open; the reading after it is the most conservative one, and the rules above apply it until a person rules.

- Q-S0060-1: how often does the publisher poll? Reading: `[cache] poll_seconds = 15`, the brief's default (rule 3).
- Q-S0060-2: does a publisher start with the conductor or on its own? Reading: with the conductor, or with the first reader that finds no live lease when no conductor runs (rule 3).
- Q-S0060-3: how long is the change log kept? Reading: 24 hours, `[cache] log_hours = 24` (rule 4).
- Q-S0060-4: the brief names `[cache] max_age_seconds` with no default. Reading: 60, four intervals of 15 seconds, so that one missed poll still reads warm and a stopped publisher is noticed within a minute (rule 5).
- Q-S0060-5: does ADR-0548's JSON read cache stay? Reading: yes, as the cache of the GitHub fallback path; retiring it is a later decision with its own ADR (rules 5 and 11).
- Q-S0060-6: is the cache on by default? Reading: `[cache] enabled = false` in the kit until build (d) passes the measured budget, and build (d) turns it on in this repository; turning it on in the kit is the release's choice (rule 12).
- Q-S0060-7: SPEC-0058's dispatcher makes its own three reads, which overlap the publisher's. Reading: SPEC-0058 is not changed here; a later patch of that spec may make the dispatcher a subscriber (rule 11).
- Q-S0060-8: the brief says both "one per clone" and "one per machine". Reading: one per git common directory, which is one per clone on its machine, and two clones on one machine each run their own (rule 3 and the residual).
- Q-S0060-9: check runs finish without changing a pull request's update time, so the delta reads cannot see them. Reading: the publisher reads, with an ETag, the check runs and status of each open head whose checks are not all complete, and stops once they are complete, until the head changes (rule 3).
- Q-S0060-10: the brief's `Measured:` before (about 700 calls and 5 minutes) disagrees with the measurement of rule 1 (22 calls cold, 23 warm, 9.6 to 13.0 seconds). Reading: the brief's figure predates brief #1261 and ADR-0548, and the goals of rule 13 stand against today's figure.
- Q-S0060-11: the brief says brief #1262 is closed into this intake when its builds are named, and #1262 is already closed. Reading: nothing more is closed; rule 11 records #1262 as superseded.
