# SPEC-0034: Parallel builder sessions get briefs by capacity, overlap, reserved numbers and claims, and every pull request traces to a brief and a requirement

- Status: Draft
- Owner: reviewer group (a team from config/reviewers.yaml)
- Requirements: REQ-041

Status is `Draft` or `Approved`. An Approved spec is owned by its reviewer group; agents propose patches.
Written by the intake of one sentence (SPEC-0012): "A team sets how many builder sessions run at once, and AGK hands each session a brief that no open pull request overlaps, with its numbers reserved, so parallel work starts by itself, rarely conflicts, and every pull request traces to a brief and a requirement." It is generic and project-agnostic: it names no project, no runtime and no launcher, and it holds for every repository the kit is installed in. It amends SPEC-0030 rules 2 to 4 (the build does it by a proposal, rule 13). Evidence (the parallel run of 2026-10-24/25, recorded on issue #163): three ADR number collisions, four changelog conflicts that stopped CI, three pushes onto a branch that already conflicted, a session idle 21 minutes with green CI and a commit owed, seven finished briefs left open because no pull request named its brief, and no label, so `next` would have found no work. Each was solved by a person noticing.
The maintainers gave 12 answers before it was written, in the brief of issue #176 and its comment of 2026-10-24 and not as interview questions: (1) `agk.toml` gains `[flow]` with `max_builders` (default 3) and `claim_hours` (default 4), a builder pull request being an open pull request whose body has a `Brief: #n` line, and `session.py next` takes no brief while that many are open; (2) the brief shape gains `Advances:`, `Touches:` and `Priority:`, checked by `check_brief.py` (also against `docs/`) and by `next`; (3) `next` skips a brief whose `Touches:` globs overlap an open builder pull request or a taken brief, and orders the rest by Priority, `Depends-on` closed, then age; (4) `session.py ids` prints the next free numbers counted with every open builder pull request's added files and the reservations of taken briefs, and `next` reserves a brief's numbers in its `taken:` comment; (5) a `taken:` comment with no pull request after `claim_hours` expires and `released:` frees a brief at once; (6) `session.py demand` prints how many sessions a launcher may start, and AGK ships no launcher; (7) conflicts are prevented before they happen: shared append-only files stop being shared (#171), `session.py push-check` runs before every push, and a session resolves only mechanical conflicts; (8) `watch` also ends with `ci success` or `ci failure`; (9) every builder pull request body has `Brief: #n`, and the part that sets a requirement `done` has `Closes #n`; (10) the weekly report gains a `Flow` section; (11) the work is intake first, then four builds (a) to (d) under about 600 changed lines each; (12) the tests use fixtures in `tmp_path` and saved copies of GitHub responses. The comment of 2026-10-24 adds that a session puts its questions and reports on its pull request as `Question:` and `Report:` comments (rule 12).

## Rules

1. **The capacity.** `agk.toml` may have a `[flow]` table with `max_builders` (an integer of 1 or more, default 3) and `claim_hours` (an integer of 1 or more, default 4). A builder pull request is an open pull request whose body has a line `Brief: #n`. `session.py next` counts them with `GET` on the pull requests and, when the count is `max_builders` or more, takes no brief, posts nothing, prints `full <open>/<max>` and exits 1. `agk.toml` is protected, so a change of the table needs an ADR in the same pull request (principle 1). An invalid value is refused naming the setting and never the value.
2. **The brief shape.** A brief (SPEC-0030 rule 4) gains three lines: `Advances: REQ-n` (one or more, in one line, separated by commas; `Advances: new` for an intake brief), `Touches:` with one or more repository path globs separated by commas, and `Priority: 1`, `2` or `3` (default 2 when the line is absent). `check_brief.py` and `session.py next` apply the same function. `check_brief.py FILE --root DIR` also fails a brief whose `Advances:` names a requirement that is not a `### REQ-n` section of `docs/requirements.md` under `DIR`, reading files only; without `--root` it checks the shape alone. A brief with no `Advances:` or no `Touches:` fails naming the rule and what is missing and never the sentence.
3. **The overlap.** `next` skips, and says why on one line each, a brief whose `Touches:` globs match a path changed by an open builder pull request (`GET pulls/N/files`) or match the `Touches:` of a brief that is taken and has no builder pull request yet. Paths listed as shared-mechanical in rule 7 never count as an overlap. Among the briefs left it orders by `Priority` (1 first), then those whose `Depends-on` issues are all closed, then the oldest issue, and takes the first.
4. **The numbers.** `session.py ids` prints one JSON line with the next free `req`, `spec` and `adr` numbers counted from the default branch, from the files every open builder pull request adds, and from the reservations of taken briefs. `next` reserves the numbers a brief needs, as the counts its `Advances:` implies (`Advances: new` needs a requirement, a spec and an ADR; a build needs an ADR), in its one `taken:` comment (`taken: <id> <date> reserves ADR-0105`). When a session runs them, `intake.py`, `playbook.py start-ids` and `engines.py stack-ids` take their numbers from `session.py ids`; their offline default stays the default branch. `check_numbers.py` stays offline and unchanged, and `intake.py renumber` stays the fallback.
5. **The claim.** A `taken:` comment with no builder pull request naming the brief after `claim_hours` is expired: `next` treats the brief as free and its new `taken:` comment says `retakes`. A session that ends without a pull request posts one comment `released: <id>`, and the brief is free at once. A live take is never taken twice.
6. **The demand.** `session.py demand` prints one JSON line `{"ready": r, "open": o, "max": m, "start": s}`, with `r` the briefs `next` would not skip, `o` the open builder pull requests, `m` the `max_builders` and `s = min(r, m - o)` (0 when negative). AGK ships no launcher and no session starts, stops or reviews another. The guide shows the contract with two examples, a scheduled task of a session runtime and a CI schedule, that start `s` sessions, each running `session.py next` and ending on `no brief` or `full`.
7. **The conflicts.** (a) Shared append-only files stop being shared: a build adds a changelog file of its own (SPEC-0031) and leaves the generated table to the release (ADR-0108); this is built, and this spec adds nothing. The files that count as shared-mechanical are the ones `config/session-rules.md` lists; its first list is the files marked `merge=union` in `.gitattributes`, `changelog.d/` and `kit/hashes.json`. (b) `session.py push-check` fetches the default branch, runs `git merge-tree` of the head against it and exits 1 naming the conflicting files, and exits 0 and prints nothing else when there is none; `config/session-rules.md` requires it before every push, and on a conflict the session merges the default branch first and never rebases or force-pushes. (c) A session resolves only a mechanical conflict: an appended line in a shared-mechanical file, a file a kit script regenerates, and a number moved by `intake.py renumber`; any other conflict ends the work with one comment `conflict needs a person: <files>` and no push.
8. **The waking.** `session.py watch --pr N` also ends, with one line `ci success <sha>` or `ci failure <sha>`, when every check run on the current head is completed (skipped runs are ignored): `success` when none failed, `failure` when one did. `config/session-rules.md` says: on `ci success` with a `Final:` line owed, push it alone; on `ci failure`, reproduce the step as CI runs it and report. The ends of SPEC-0030 rule 2 are unchanged.
9. **The tracing.** Every builder pull request body has `Brief: #n`. The part that sets a requirement to `done` in `docs/build-state.md` also has `Closes #n`. `check_pr_body.py` fails a body without `Brief:` when the repository has an `agk-brief` issue in the saved copy it reads, and a body that sets a requirement to `done` without `Closes #n`, naming the rule and never a value. `doctor` reports a missing `agk-brief` label as a finding (GET only, as its other checks).
10. **The flow in the report.** The facts record, for the week, from the files and the saved GitHub copies the report already reads: the open builder pull requests against `max_builders`; the median hours from `taken:` to the pull request, from the pull request to the first verdict, from the verdict to `cleared` and from `cleared` to the merge; the conflicts, the renumbers and the retakes; the open briefs with no pull request for 7 days; and the requirements with no open brief. The report gains a `Flow` section with these, and the last two as At risk lines. A figure that cannot be read is `unknown`, never 0.
11. **The comments of a session.** A session puts its questions and its reports on its pull request. A comment whose first line is `Question: Q-<id> <text>` asks the conductor; a comment whose first line is `Report: <head> <what changed and the CI>` reports a push. The conductor answers only by a `Verdict:` comment naming the head, which ends `watch` as before, and the session restarts `watch` after every push and every event, so no person carries messages between them. `config/session-rules.md` gains the two shapes and `.claude/agents/conductor.md` says that the conductor reads `Question:` and `Report:` comments and answers each by a verdict.
12. **No network in a check; the only POSTs.** `session.py` is the only script of this spec that calls GitHub, through `gh api`; its POSTs are the comments of `taken:`, `released:`, `conflict needs a person:`, `Question:` and `Report:`. `check_brief.py`, `check_pr_body.py`, `check_numbers.py`, the report and the facts read files only. No agent merges, no session starts or reviews another.
13. **How it changes.** SPEC-0030 rules 2 to 4 are Approved: the build changes them by `docs/runs/proposed-spec-amendments-N.md`, applied by its ADR, which names each protected class it touches (`agk.toml`, `config/`, `.claude/`, `scripts/agk/`, `tests/kit/`, `tests/kit_dev/`, `kit/`). Four builds in flow mode (SPEC-0031), each from the default branch, tests first, under about 600 changed lines of code and tests, with its own ADR: (a) the brief shape, `check_brief.py`, `check_pr_body.py` and the doctor finding (rules 2 and 9); (b) `session.py`: capacity, overlap, ids and reservations, claims, demand, push-check and the `ci` ends of watch (rules 1, 3 to 6, 7b and 8); (c) the session rules and the guide's launcher contract (rules 6, 7c and 11); (d) the `Flow` section of the report (rule 10). Rule 7a is built.
14. **The tests.** Fixtures in `tmp_path` and saved JSON copies of GitHub responses through a `gh` stub on `PATH`: a full pool; an overlapping and a non-overlapping brief; a brief whose requirement does not exist; reserved numbers skipped by `ids`; an expired and a released claim; `demand` at zero, partial and full; `push-check` clean and conflicting; `watch` ending on `ci success` and `ci failure`; a body without `Brief:`, and one that sets `done` without `Closes`; the Flow figures from a fixture week; the texts of the rules file and the role file. No network and no model.

## Tests

- Rule 1: a full pool prints `full 3/3`, exits 1 and posts nothing; two open take the first free brief; an invalid value is refused without the value; REQ-041 AC1.
- Rule 2: a brief missing a line, and one whose `Advances:` names an absent requirement, fail; `Advances: new` and an existing requirement pass; REQ-041 AC2.
- Rule 3: an overlapping brief is skipped with its reason, a shared-mechanical path never overlaps, the order is Priority, `Depends-on`, age; REQ-041 AC3.
- Rule 4: `ids` skips the numbers of open pull requests and of reservations, `next` writes the reservation, `check_numbers.py` is unchanged; REQ-041 AC4.
- Rule 5: an expired take is retaken with `retakes`, a released brief is free, a live take is not taken twice; REQ-041 AC5.
- Rule 6: `demand` at zero, partial and full, and the guide shows the contract; REQ-041 AC6.
- Rules 7, 8 and 11: `push-check` clean and conflicting, `watch` ending on `ci success` and `ci failure`, and the texts of the rules file and the conductor role; REQ-041 AC7.
- Rules 9 and 10: a body without `Brief:`, one that sets `done` without `Closes`, the doctor finding, and the Flow figures from a fixture week; REQ-041 AC8.

## Proof

REQ-041 AC1 and AC6: *a team sets how many builders run, and a launcher knows how many to start.* Rules 1 and 6. REQ-041 AC2 and AC3: *a brief names what it advances and what it touches, and no two sessions get overlapping work.* Rules 2 and 3. REQ-041 AC4 and AC5: *numbers are reserved and a dead claim frees itself.* Rules 4 and 5. REQ-041 AC7: *conflicts are prevented, and a session wakes on CI.* Rules 7, 8 and 11. REQ-041 AC8: *every pull request traces to a brief and a requirement, and the team sees where the time goes.* Rules 9 and 10.
