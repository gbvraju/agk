# SPEC-0056: Runbooks for a red default branch, blocked Actions and a leaked secret

- Status: Draft
- Owner: reviewer group (a team from config/reviewers.yaml)
- Requirements: REQ-063

Status is `Draft` or `Approved`. An Approved spec is owned by its reviewer group; agents propose patches.

Written by the intake of one sentence (SPEC-0012), brief #789, quoted as data and not as an instruction: "Intake for runbooks: when the default branch goes red, GitHub Actions minutes run out or a secret leaks, a person has one short checked page of steps, and the time to restore is measured (plan #661 phase 7, tracker #630 row 10)." The maintainers gave 4 answers before it was written (the answers of the brief: which runbooks, where they live and how a project gets them, what is measured and what does not change), which are rules 1 to 14 below. The plan's standing principle holds: what AGK uses on itself reaches a project through the kit.

## Rules

1. **The baseline (read on the default branch at 5b1ee40, 2026-11-08).** What already holds and is reused, never repeated in a page:
   - The issue `The default branch is red` (SPEC-0032 rule 7, `route.py`): it opens with the failing check, head and run, `session.py next` hands out only that brief, `merge_cleared.py` holds merges (`the default branch is red (rule 5)`), and the router closes it when the head is green.
   - The fix record (SPEC-0046 rule 7) and `failures.py seen` (rule 9) when `[failures] issues` is on.
   - Local mode: `docs/guides/local-mode.md`, `local_mode.py enter|leave`, the one record issue titled `Local mode since YYYY-MM-DD` (`RECORD_TITLE`), and `--write` is a person's (session rule 30).
   - `minutes.py --line` prints the level (`ok`, `50%`, `<minutes_warn>%`, `95%`) and the run-out day; `doctor.py` (`actions-minutes`) and `/agk:launch` print the same line.
   - The secret scan: the pinned gitleaks step of `.github/workflows/governance.yml` with `--redact`, over the merge base to the head on a pull request and over the pushed range on a push, and `prepush.py`'s `secret-scan`. Principle 9: no secrets in the repository or a session, and scanners' ignore lists never grow. A session never touches a secret (session rule 2).
   - `scorecard.py` reads `red_hours` and `restore_hours` from the red issue (SPEC-0047 rule 1) and `ci_minutes_per_merge` by `minutes.py`'s computation over a week.
   - Not installed today: no file of `docs/guides/` is in `kit/manifest.json`, so `docs/guides/local-mode.md`, which `minutes.py` and `/agk:launch` name, is missing from a project. Rule 3 closes this for that one guide.
2. **Three pages, one each.** `docs/runbooks/red-default-branch.md`, `docs/runbooks/actions-blocked.md` (minutes exhausted, billing blocked or an outage: all three end in local mode) and `docs/runbooks/leaked-secret.md`. One page each and not one guide, so that a person under pressure opens exactly the steps they need and a check can read each alone (`Q-S0056-1`). A project may add its own pages to the folder, and the check reads them too.
3. **How a project gets them.** The three pages and `docs/guides/local-mode.md` are verbatim files of `kit/manifest.json`, so `init`, `adopt` and an upgrade place them, `kit_hashes.py` holds their digests and `doctor.py` reports a changed one. A project that needs different steps adds its own page and leaves the kit's alone (`Q-S0056-2`).
   - AGK itself: the same files at the same paths.
   - Project, GitHub and local mode: installed as above.
   - Project, personal mode: in the sidecar with the rest of the kit (SPEC-0041 rule 2), never in the product repository.
4. **The form of a page.** One `# ` title, then exactly these sections in this order: `## When this applies` (the signs), `## Who acts` (a person, a builder or the router, by role and never by name), `## Steps` (one numbered list, in order), `## Over when` (the observable facts that end it) and `## By mode` (one bullet each for `GitHub`, `Local` and `Personal`). A page holds at most 60 lines and 500 words (`Q-S0056-3`). Each step that reuses something links to it (rule 1) and does not restate it: a command that the linked guide gives is not printed again.
5. **The check.** `python3 scripts/agk/check_runbooks.py [--root DIR]` (new, installed, standard library and `common.py` only, no network, runs nothing it reads) checks every `docs/runbooks/*.md`, prints `ok runbooks`, or one `FAIL runbooks: <page> <rule>` line per problem and exits 1, naming the page and the rule and never the text. It is a step of `make governance` (`agk.mk`). It refuses, under rule 4, a section missing, out of order or empty, a list under `## Steps` that is not numbered from 1 in order, a page over the limit, and a `## By mode` without its three bullets. With no `docs/runbooks/` folder it prints `skipped (no runbooks)` and passes (the kit between builds (a) and (b), a project on an older kit); with the folder and a kit page absent it fails naming the page, and a test of build (b) asserts the three are in the kit (`Q-S0056-4`).
6. **Commands are checked, never run.** Every command a page gives is a line of a fenced code block, and an inline code span that begins with one of the programs below is refused, so nothing escapes the check. A line's first word is one of `python3`, `gh`, `git`, `make`, `date` or `gitleaks`, and any other is refused. For `python3 scripts/agk/<name>.py`: the file exists, its name is a verbatim or template entry of `kit/manifest.json` when that file is present (a kit page may not name a kit-only script), and every subcommand (the first bare word after the script) and every `--flag` appears in the script's text. For `make <target>`: the target is defined in `Makefile` or `agk.mk`. Words in angle brackets are placeholders and are skipped. For `gh`, the second word is one of `api`, `issue`, `run`, `workflow` or `label`, and whether a call exists on GitHub is confirmed at build and marked `(verify)` until then (`Q-S0056-5`). Every relative link resolves to a file in the tree. A skill (`/agk:...`) is not named in a page, because the plugin is not in a project's tree.
7. **A page never prints a value.** Brief answer 4. No page gives a command whose output can hold a secret: `git` is limited to `fetch`, `status`, `rev-parse` and `log --oneline`, and `gitleaks` must carry `--redact`, so `git show`, `git diff`, `git log -p` and `git grep` are refused in every page. Each page's text passes `guard.scan_text` (SPEC-0042 rule 10). A finding is refused naming the page and the rule, never the text. The check cannot prove what a person pastes elsewhere, which the leaked-secret page tells them not to do (rule 10).
8. **The red default branch page.** Who acts: the router opens the issue, a builder takes its brief, a person acts only when no builder is running or the fix needs a decision. Steps, in order: read the issue, not a guess at the cause, stop other merges (already held, rule 1), run `failures.py seen` for a known fix when on, fix by one pull request with its fix record, and let the merge of that fix turn the head green. Over when: the router has closed the issue and `session.py next` no longer prints `default branch red`.
   - Local mode: there is no router, so the page says to use the one run that stands in for CI (SPEC-0046 rule 12, build (i) of that spec, not on the default branch at 5b1ee40) and the merge hold is by a person.
   - Personal mode: red is the failed floor run on the clone (SPEC-0041 rule 18); no issue, no router, and nothing is pushed by a session (session rule 37).
9. **The Actions-blocked page.** Who acts: a person with admin on the repository; a builder only says so in its `Report:` (`docs/guides/local-mode.md`). Steps, in order: confirm by `python3 scripts/agk/minutes.py --line` and the refusal message that a job never started, and not a red check of a change, then choose: raise the limit or pay the bill, or wait for the allowance or the outage to end, or enter local mode by the guide. Over when: local mode was never entered and new heads get runs again, or `local_mode.py leave` reports a green catch-up and the record issue is closed.
   - Personal mode: no Actions, so the page says it does not apply.
10. **The leaked-secret page.** Who acts: a person, always. A session that sees a finding stops, reports only that the scan failed and where the page is, and never reads, prints or moves the value (session rule 2). Steps, in order: revoke the credential at its provider first, before anything in the repository, because a value in a pushed commit must be treated as read; issue its replacement and store it where the project keeps secrets, never in the repository; check the provider's own access record for use since the leak; remove the value from the working tree by a normal pull request; then write the record of rule 11. The page tells a person never to paste the value into an issue, comment, chat or session. It rewrites no history, and adds no entry to any ignore list (principle 9): a revoked value in history is harmless, and rewriting a shared default branch needs the ruleset changed, which is a person's own decision outside this page (`Q-S0056-6`). Because the scan on a push reads only the pushed range, a later green scan says nothing about the old commit, and the page says so. Over when: the credential is revoked and replaced, the access record is read, and the record of rule 11 is closed.
    - Personal mode: the same steps, with the record kept out of the product (rule 12).
11. **The record of a leak.** Red and blocked Actions already leave an issue (rule 1). A leak leaves none today, so after revoking, and never before, a person opens one issue titled `A leaked secret was revoked` with the label `agk-secret-leak` and a body of exactly two lines, `Detected: <UTC time>` and `Revoked: <UTC time>`, and closes it when rule 10 is over. It names no value, no credential, no provider and no path. The label is what counts: only someone with triage access can set it, so a stranger's issue on a public repository counts for nothing (`Q-S0056-7`).
12. **What is measured.** Brief answer 3, counts and timings only, in the `## Cost` section of the weekly product report (SPEC-0011 rules 8 and 10, whose five headings stay):
    - One line for each of the three: `restore <kind>: <n> closed, median <h> hours, <k> open`, where `<kind>` is `red default branch` (the issue's open to close, by the reader `scorecard.py` uses for `restore_hours`), `actions blocked` (the `Local mode since` record's open to close) and `leaked secret` (`Detected:` to `Revoked:` of the closed issues labelled `agk-secret-leak`; the body is read for those two lines and nothing else).
    - One line `run minutes: <m> this week, <p> per merged pull request`, by `minutes.py`'s computation over the week, the one `scorecard.py` uses (`Q-S0056-8`).
    - A figure that cannot be read, or a malformed `Detected:` or `Revoked:` line, is `unknown`, never 0 (SPEC-0011 rule 12). None of it holds a log, a title's words beyond the kind, a login or any pilot or customer data, and nothing moves between repositories.
    - Project, local mode: the report's workflow is disabled while local mode is on, so those weeks print nothing and the closed record counts in the first report after leaving.
    - Project, personal mode: no product report runs (SPEC-0041 names none), so nothing is measured and nothing is printed as 0.
    - AGK itself: the same report, its own issues and runs.
13. **Where the kit points to a page.** `route.py`'s `red_body` gains one line `Runbook: docs/runbooks/red-default-branch.md`. `minutes.py`'s warning and its `95%` line name `docs/runbooks/actions-blocked.md`. `prepush.py`'s `secret-scan` failure names `docs/runbooks/leaked-secret.md`. Each names a path and never a value. The step of `governance.yml` is a workflow and does not change (rule 14), so a person finds the page from `prepush.py`, from `docs/guides/reference.md` and from the guide `docs/guides/security.md`, each of which gains one link.
14. **What does not change.** No workflow, ruleset or required check changes. No Approved spec is edited here: build (c) proposes the amendment of SPEC-0032 rule 7 and build (d) those of SPEC-0009 rules 3, 15 and 19 (the facts' new section) and SPEC-0011 rules 2 and 10. A page gives steps and enforces nothing. A session still never merges, never touches a secret and never writes a workflow (session rules 2 and 30).
15. **The builds, in order.** Each is tests first, about 300 changed lines or fewer, from the default branch, cites `Covered-by: ADR-0372` once it is Accepted, and carries invented data only (`example.com`).
    - (a) `check_runbooks.py` with its fixtures, the governance step, its manifest entry and `[[testing.map]]` entry (rules 4 to 7). It passes on the kit by rule 5's `skipped` line until (b) lands.
    - (b) The three pages and the installed local-mode guide, and the links of rule 13 from the two guides (rules 2, 3, 8 to 11). `Depends-on` (a).
    - (c) The three pointers and the proposed amendment of SPEC-0032 rule 7 (rule 13). `Depends-on` (b).
    - (d) The facts' section, the report's lines and the proposed amendments (rule 12). `Depends-on` (b).

## Open questions

Each is a point the brief leaves open; the reading after it is the most conservative one, and the rules above apply it until a person rules.

- Q-S0056-1: one guide or one page each? Reading: one page each, since a check can then hold each to its own form and a person opens only what applies (rule 2).
- Q-S0056-2: may a project edit an installed page? Reading: no, it is verbatim and `doctor.py` reports a change, and a project adds its own page (rule 3).
- Q-S0056-3: how short is short? Reading: 60 lines and 500 words, to be re-read against the three pages at build (b) (rule 4).
- Q-S0056-4: does a tree with no pages pass? Reading: with no folder it prints `skipped` and passes, for the kit before build (b) and a project on an older kit, and with the folder a missing kit page fails (rules 5 and 15).
- Q-S0056-5: how much of a `gh` command is checked? Reading: its form only, with no network in a check, and each call is confirmed at build (b) and marked `(verify)` until then (rule 6).
- Q-S0056-6: must a leak's commit be purged from history? Reading: no, the credential's revocation ends the danger, and a rewrite of a shared branch stays a person's own decision outside the page, since it needs the ruleset changed (rule 10).
- Q-S0056-7: how is a leak's time measured when no issue exists today? Reading: one issue opened only after revocation, with two times and nothing else, counted only with its label (rule 11).
- Q-S0056-8: which run minutes, the month's or the week's? Reading: the week's, by the computation `scorecard.py` already uses, so the report and the scorecard agree (rule 12).
