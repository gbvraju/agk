# ADR-0716: A brief's later build is not refused for a file its own earlier build added

- Status: Proposed
- Date: 2026-11-22
- Deciders: maintainers
- Related: brief #1717, ADR-0691 (brief #1660), brief #1583
- Requirements: REQ-041

## Context

`session_plan.touch_problems` refuses an `Adds:` entry that matches any file of the default branch outside the
shared-mechanical files, and read nothing of the brief's own history. A multi-build brief whose first build added a
file its `Adds:` line names was therefore refused as malformed for its next build (#1583 after #1612 and #1647):
`session.py plan --what-if` on f1d2f05 printed `MALFORMED: b1583.md rule 4: Adds entry .claude/hooks/branch_check.py
names an existing file`, and a person had to edit the brief. The tests were written first
(`tests/kit/test_plan_exact_touches.py`: 21 failed on the unchanged tree).

## Decision

1. **The exemption** (`scripts/agk/session_plan.py`, `touch_problems`). It takes `own`, the files the brief's own
   merged pull requests added; an `Adds:` entry whose every match in the tree is in `own` is not refused. Any other
   match is refused as today, so a glob over one own file and one other file is refused.
2. **How `own` is read** (new `own_added`, with `timeline_pulls` split out of `history_of`). Only when an `Adds:`
   refusal would be returned for a numbered brief: one read of its timeline, and the files of each pull request on it
   that is merged and names `Brief: #<n>`, keeping those with status `added`. A timeline or file list that cannot be
   read leaves `own` empty: refused as today (fail closed). A closed unmerged pull request, another brief's pull
   request and a file that was modified rather than added give nothing.
3. **Where it applies** (`scripts/agk/session.py`, `brief_shape` and `judge`). The shape built by the survey gets the
   survey and the brief's number, so `next`, `claim` and `plan` agree. `check_brief.py` (a saved file and the
   `agk-brief` job) and `plan --what-if` (saved briefs have no number) pass no `own` and read no network: unchanged.
4. **No setting reads it, and no new key.** `default_branch`, `[flow] max_touch_glob`, `shared_indexes`,
   `claim_hours`, `assign`, `builder_start`, `max_builders`, `pr_mode`, `review_mode`, `execution` and `[kit] layout`
   leave the exemption as it is (one test each); a shared index is exempt only when it is the brief's own; a
   `merge=union` file never refuses. In personal mode (`forge = "files"`) no pull request exists, so `own` is empty and
   the refusal stays (Q-1717-1).

Protected path classes changed: `scripts/agk/` (`session.py`, `session_plan.py`) and `tests/kit/`
(`test_plan_exact_touches.py`); `kit/hashes.json` is regenerated by `kit_hashes.py`, never edited by hand.

## Consequences

The next build of a multi-build brief starts without anyone editing the brief. An edited multi-build brief may still be
labelled `agk-brief-invalid` by the network-free brief job while the plan offers it (Q-1717-2); the steward's fix
writes the remaining build's `Adds:` as `Adds: none`.
