# ADR-0109: the late-clearance check, the ready-to-merge group and the guide section on the loop (REQ-037 part c, SPEC-0030 rules 7 to 9)

- Status: Proposed
- Date: 2026-10-24
- Deciders: maintainers
- Related: ADR-0105, ADR-0102, ADR-0100, ADR-0098, ADR-0079
- Requirements: REQ-037

Protected classes: `kit/`, `scripts/agk/`, `tests/kit/`, `tests/kit_dev/`

## Context

SPEC-0030 (Approved, #167) rules 7, 8 and 9 are the last build (c) of issue #163. The tests were written first (`tests/kit/test_clearance_lateness.py`, `test_report_ready.py`, `test_head_cleared.py`, `tests/kit_dev/test_report_ready_schema.py`, `test_guide_loop.py`; on the unchanged tree most of them failed). The residual of ADR-0079 (a clearance two or more commits late passes unchecked) is closed by rule 7.

## Decision

1. **Late clearance** (rule 7): `check_final_clearance.py` fails with `rule 7` when the latest covered fix list's reviewed sha is two or more commits behind the head on the first-parent line; the other cases are unchanged.
2. **Facts** (rule 8): `head_cleared` for an open pull request (`yes`, `no`, `unknown`); the facts keep schema 1; the goldens of the facts are regenerated by `tests/kit/test_facts.py --write-goldens`.
3. **Report** (rule 8): the group `ready` first in Needs you, the kind `pull-request-ready`, schema number 4 in `product_report.py`, `kit/report-schema.json` and every golden; the markdown line `PR #<n> "<title>" is ready to merge`.
4. **Guide** (rule 9): the section "Running the loop" in `docs/guides/getting-started.md`, with an example brief that the test checks with `check_brief.py`.
5. Flow mode: no version bump, one line under `## Unreleased` of `CHANGELOG.md`, hashes refreshed. Amendment 55 (`docs/runs/proposed-spec-amendments-55.md`) is applied to SPEC-0021, SPEC-0009, SPEC-0022 and SPEC-0026. `docs/requirements.md` is not changed: REQ-037 stays `planned` until the maintainers set it (the learnings of issue #163 are further parts).

## Consequences

- A late `Final:` commit can no longer pass the check unseen; the maintainers see what is ready to merge first in the report.
- A project that upgrades gets schema 4 of `report.json`; a reader pinned to schema 3 must accept 4.

## Residual

None beyond SPEC-0030's.
