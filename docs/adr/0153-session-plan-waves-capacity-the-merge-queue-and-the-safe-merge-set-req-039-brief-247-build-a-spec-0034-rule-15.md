# ADR-0153: `session.py plan`, waves, capacity, the merge queue and the safe merge set (REQ-039, brief 247 build (a), SPEC-0034 rule 15)

- Status: Accepted
- Date: 2026-10-26
- Deciders: maintainers
- Related: ADR-0124, ADR-0150
- Requirements: REQ-039

Protected classes: `kit/`, `scripts/agk/`, `tests/kit/`

## Context

Brief #247 (priority 1, measured 2026-10-26): starting each builder session is a manual step, and `session.py demand` is too naive to plan on. It printed `{"ready": 4, "open": 0, "max": 3, "start": 3}` while builder-a was already building #244 build (a) with no pull request yet and while several open briefs were stale: it counts neither claims without a pull request, nor overlap, nor the merge queue. This is build (a): the plan. Build (b), `/agk:start` and its adapter, is a later build. The tests were written first.

## Decision

1. **`session.py plan [--json]`** (`scripts/agk/session_plan.py`, imported by `session.py` when the command runs). It reads what `next` and `demand` already read, the files and labels of the open pull requests and one `compare` read for each ready pull request. It posts nothing, runs no model and starts nothing. Plain words by default; `--json` prints the same plan as data (`start`, `waits`, `skipped`, `capacity`, `merge`, `merge_set`, `behind`, `behind_unknown`, `conflicts`).
2. **Waves.** A brief whose `Touches:` overlap running work waits for it, and of two ready briefs that overlap the later by priority and then number waits and is named with the brief it waits for and the broader of the two globs. The shared mechanical files never overlap. Against a running pull request only the files it modifies, renames (also by the old name) or removes are matched against the `Touches:` globs; a file it only adds blocks only on an exact path (the verdict on 79631d7: every build adds an ADR, a changelog fragment and tests, so counting them would make every brief wait for every other). `next` keeps its own rule (SPEC-0034 rule 3) for now (Q-247-5).
3. **Capacity.** The sessions to start are the smallest of the ready non-overlapping briefs, `max_builders` less the running builders (open builder pull requests and claims with no pull request yet) and `reviews_in_flight` less the pull requests labelled `agk:review`. Sessions are named `builder-a`, `builder-b`, ... skipping the names with a live take, which includes a take whose open pull request names the brief. `session.py` reads a take or a release comment without the attribution footer the server adds (`---` and a `Generated by` line): before this, a claim posted with the footer was not read as a take at all, so a running session looked free (found on the verdict on 79631d7 and measured on this repository).
4. **The merge queue, measured.** Merges per active hour over the last 14 days, an active hour being an hour-long bucket, counted back from now, that holds a merge. While the `agk:ready` pull requests exceed `merge_hours` times the rate, no session starts and the plan says so; with no merge in the window the limit does not apply and the plan says the rate is unknown.
5. **The safe merge set.** The `agk:ready` pull requests that share no changed file, ordered by the briefs each unblocks (waiting briefs named for it), then priority, then age, with protected paths marked; a pull request that shares a file goes after the one it shares with.
6. **Drift.** A ready pull request more than `stale_commits` behind, and an `agk:conflict` pull request, are listed for their builder. A `compare` that cannot be read is `behind_unknown`, never zero.
7. **Stale briefs.** `Status: stale` or the label `agk-stale`: `plan` and `next` skip it with the reason `stale`.
8. **Settings.** `[flow] reviews_in_flight` (3), `merge_hours` (1) and `stale_commits` (20), each a whole number of 1 or more, refused otherwise naming the setting. They are read from the `[flow]` table like `max_builders`; no template carries them.
9. **Readings taken where the brief leaves a point open** (the most conservative each, as questions on the pull request): "active hour" is the bucket defined in item 4; the label of a stale brief is `agk-stale`; the pipeline document gets no optional field for the safe merge set, because SPEC-0036 rule 2 lists exactly the fields of schema 1 (a follow-up); the pull requests waiting for a verdict are those labelled `agk:review`. Amendment 88 (`docs/runs/proposed-spec-amendments-88.md`) is applied to SPEC-0034 (new rule 15). Flow mode: fragment `changelog.d/session-plan.md`; no version bump.

## Consequences

- A person sees one plain plan of how many sessions to start and why the others wait, before any session starts.
- `next` no longer hands out a stale brief.

## Residual

- 2026-10-26: the plan counts the merge rate of every merge, not of one person, and the safe merge set cannot tell a semantic conflict between pull requests that share no file (due 2026-12-31).
