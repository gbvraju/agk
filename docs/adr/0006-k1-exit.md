# ADR-0006: K1 exit

- Status: Accepted
- Date: 2026-10-14
- Deciders: maintainers
- Related: ADR-0001, ADR-0004, ADR-0005
- Amends: ADR-0001
- Requirements: REQ-005, REQ-009

## Context

K1 is proven (`docs/runs/k1-live-proof.md`). Closing it leaves the residuals the live proof and earlier ADRs
carried: unpinned action tags, duplicate CODEOWNERS lines for a path in two classes, no check for principle 6, and
a handle residual that no longer matches the plan. ADR-0001 is Accepted and immutable except its Status, so this ADR
amends its handle residual instead of editing it.

Protected classes: `.github/`, `scripts/agk/`, `tests/kit/`, `tests/kit_dev/`, `Makefile`, `kit/`.

## Decision

1. **SHA pins.** Every action in `.github/workflows/governance.yml` is pinned to a full commit SHA with the tag in a
   comment. A test requires every `uses:` line to be a 40-character SHA. Sources are in `docs/runs/day-4.md`.
2. **CODEOWNERS dedupe.** `reviewers.render_codeowners` emits each path once; when a path is in two classes the later
   class wins; the ordering rule is unchanged. `.github/CODEOWNERS` is regenerated.
3. **Approved-spec check.** `scripts/agk/check_specs.py`, run by `make governance` and installed through the
   manifest, fails a PR that modifies or deletes a spec whose base version is `Status: Approved` unless the same PR
   adds or modifies a `docs/runs/proposed-spec-amendments-*.md` that names the spec's path. A Draft spec, a new spec
   and the Draft to Approved flip pass. This implements principle 6.
4. **Handle residual (amends ADR-0001).** The `maintainers` mapping to a user handle stays until a second maintainer
   joins; replace it then with an organisation team. This replaces the "replace by K1 exit" wording of ADR-0001.
5. **Installed ADR-0001.** The template's decision 3 names the repository's creation commit as its one direct
   commit, as this repository's ADR-0001 does.
6. **README.** An "Installing" section: empty target, one first commit, maintainer-approved init, ruleset by hand.
7. **Kit version** `0.2.0` in `kit/manifest.json`: installed content changed.

## Consequences

- A change to an Approved spec is visible as a proposed amendment, and the amendment file is the review record.
- Action upgrades are manual: each new tag needs a new SHA looked up and recorded.
- The pinned tags are the latest patch of the majors the workflow already used (`v4`, `v5`, `v2`).

## Residual

- 2026-10-14: the SHAs were confirmed only by `git ls-remote` against the official repositories; signatures were
  not checked, and no attestation was verified.
- 2026-10-14: evaluate newer majors of the actions (checkout v7, setup-python v7, gitleaks-action v3 exist as tags)
  in a dedicated PR (Q-K1-16).
- 2026-10-14: the gitleaks-action licence terms for organisations are still unconfirmed; the repository is under a
  user account. Proposed resolution: replace gitleaks-action with the MIT gitleaks binary (verify licence) so
  organisation-owned targets need no key; K2 or K4 (Q-K1-17).
- 2026-10-14: `check_specs.py` treats any change to an Approved spec, including a Status-only change, as needing an
  amendment (conservative).
- 2026-10-14: class naming in an ADR is still a substring match (ADR-0003 residual).
