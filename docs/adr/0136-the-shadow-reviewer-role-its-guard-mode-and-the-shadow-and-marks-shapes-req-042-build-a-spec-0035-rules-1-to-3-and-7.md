# ADR-0136: the shadow reviewer role, its guard mode and the Shadow and Marks shapes in the session rules (REQ-042 build a, SPEC-0035 rules 1 to 3 and 7)

- Status: Proposed
- Date: 2026-10-25
- Deciders: maintainers
- Related: ADR-0129, ADR-0105, ADR-0125
- Requirements: REQ-042

Protected classes: `.claude/`, `config/`, `kit/`, `tests/kit/`, `tests/kit_dev/`

## Context

SPEC-0035 (Approved, ADR-0129) rule 9 makes build (a) the shadow role file with its guard line, the `agk-shadow` issue and the `Shadow:` and `Marks:` shapes in the session rules; the conductor assigned it on #207 with this ADR number and amendment 72 reserved, and `builder-b` took it on #204. The tests were written first (`tests/kit/test_shadow_guard.py`, `tests/kit/test_shadow_rules.py`, `tests/kit_dev/test_shadow_role.py`).

## Decision

1. **The shadow role** (`.claude/agents/shadow.md`, installed verbatim, listed in `kit/manifest.json`): a role file of its own, as the maintainer ruled on Q-S0035-1 (the conductor's file is not reused, because it posts verdicts). It reviews every head the conductor gives a verdict on (Q-S0035-6), reads the pull request, its checks and its diff and never the verdict comments of the conductor before it posts, posts one `Shadow: #<pr> <sha> cleared|fix list|rejected` comment with numbered findings `S1.`, `S2.` on the one open issue labelled `agk-shadow`, and never posts a verdict, writes a `Marks:` comment, edits a file, merges or controls a session. Its protocol block is the architect's, as the conductor's is.
2. **The guard line** (`.claude/hooks/conductor_guard.py --shadow`): the same guard with one argument. The one comment `POST` is allowed only with exactly one `-f` field whose value is `body=Shadow: #<pr> <sha> cleared|fix list|rejected` followed by anything, given inline or, for the findings of several lines, as `-F body=@<file>` where the file is a regular file inside a scratch directory (`scratch_dir`, as for the bounded run) whose first line has that shape; the guard reads the local file and needs no network. A verdict, a `Marks:` comment, a file elsewhere, a link out of the scratch directory, a wrong first line or a second field is denied; reads, the bounded run and every other denial are the conductor's; any other argument denies everything; the conductor's own mode is unchanged (a later item) (Q-K4-304, Q-K4-305, the verdict on f18b7d7).
3. **The session rules** (`config/session-rules.md`): rule 25 gives the `Shadow:` shape, that only the shadow posts it, on the one issue labelled `agk-shadow`, and its blindness; rule 26 gives the `Marks:` shape on the pull request after it merges, who writes it (the maintainer for the first sample of ten, then the builder, the person who merges when the builder has ended) and that a reviewer never marks its own findings and an unmarked head is never zero (Q-S0035-3 and Q-S0035-4 as ruled). The numbers 25 and 26 follow rule 24 of main (Q-K4-306).
4. **Not in this build**: `shadow_count.py` (build b), the report line and its schema raise (build c), and any check or command that creates or tests the `agk-shadow` label: a person creates the issue and its label (Q-K4-307).
5. Flow mode: no version bump, the fragment `changelog.d/ccr-7649d887-m9hvn7-se.md`, `CHANGELOG.md` and `kit/hashes.json` as on main. Amendment 72 (`docs/runs/proposed-spec-amendments-72.md`) is applied to SPEC-0030 rules 1 and 6.

## Consequences

- A team can run a second reviewer that cannot post a verdict, with a guard that refuses every other write; the marks and the count wait for builds (b) and (c).
- The kit has one more verbatim role file; its hash row is regenerated by the release, not by this build.

## Residual

- 2026-10-25: the guard cannot tell the `agk-shadow` issue from another issue or a pull request without a network call, so it checks the shape of the body and the issue-comment endpoint of the origin repository; that the issue is the labelled one is the role file's rule (due 2026-12-31).
- 2026-10-25: no command yet posts a `Shadow:` or a `Marks:` comment; sessions post them with their runtime's tools until a build adds the commands (due 2026-12-31).
