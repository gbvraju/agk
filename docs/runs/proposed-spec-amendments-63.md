# Proposed spec amendments 63 (SPEC-0030; REQ-041)

Date: 2026-10-25 (from `date -u`). Approved specs change only through a proposal like this one (principle 6). Applied by ADR-0125. The path: `docs/specs/0030-a-conductor-role-reviews-every-pull-request-posts-the-verdic.md`.

1. **SPEC-0030 rule 1, the session rules.** `config/session-rules.md` also holds, as SPEC-0034 rules 7b, 7c and 11 say: `session.py push-check` before every push, and on a conflict the default branch is merged first and never rebased or force-pushed (rules 13); the list of shared-mechanical files, which are the files marked `merge=union` in `.gitattributes` and `changelog.d/`, with `kit/hashes.json` named as a release file that a build never edits (14); that a session resolves only a mechanical conflict (an appended line in a shared-mechanical file, a file a kit script regenerates, a number moved by `intake.py renumber`) and otherwise posts one comment `conflict needs a person: <files>` and pushes nothing (15); and the two shapes a session puts on its pull request, `Question: Q-<id> <text>` and `Report: <head> <what changed and the CI>`, which the conductor answers only by a `Verdict:` comment that names the head (16).
2. **SPEC-0030 rule 6, the conductor.** `.claude/agents/conductor.md` says that the conductor reads the `Question:` and `Report:` comments of each pull request and answers each by a verdict, never by another message, so that no person carries messages between it and a session.
3. **SPEC-0034 rule 5, the claim.** A `taken:` comment may end with `build (<x>)` and `released:` with `[build (<x>)]`; a live take of a build is never taken twice, a take without a build part claims the whole brief, and expiry and release apply per build. `session.py claim --session ID --brief N [--build X]` posts the take.
4. **SPEC-0034 rule 12, the POSTs.** The `Request: <id> finished #<brief>` or `Request: <id> new` comment on the one open issue labelled `agk-conductor`, and the conductor's answer, one comment whose first line is `Assign: <id> #<n> [build (<x>)]` or `Assign: <id> none`. `session.py watch --assign ID` ends on that line by a listed verdict author, or on `assign-timeout` after `claim_hours`.
5. **SPEC-0034 rule 1, the setting.** The `[flow]` table gains `assign`, `"conductor"` or `"next"` (default `"next"`); `session.py after --session ID` acts on it, and an invalid value is refused naming the setting and never the value.
