# Proposed spec amendments 60 (SPEC-0030; REQ-041)

Date: 2026-10-25 (from `date -u`). Approved specs change only through a proposal like this one (principle 6). Applied by ADR-0124. The path: `docs/specs/0030-a-conductor-role-reviews-every-pull-request-posts-the-verdic.md`. The number 60 is the next one free on the default branch when this was written. It builds rules 1, 3, 4, 5, 6 and 7b of SPEC-0034 (Approved), which name this change.

1. **SPEC-0030 rule 3, what `session.py next` reads and in what order.** `next` first reads every pull request and the open `agk-brief` issues. It takes nothing, posts nothing, prints `full <open>/<max>` and exits 1 when `max_builders` builder pull requests are open (SPEC-0034 rule 1). It skips, on one line each, a brief that fails the shape of rule 4, a brief with an open `Depends-on` issue, a brief taken by another session, and a brief whose `Touches:` overlap an open builder pull request or a taken brief (SPEC-0034 rule 3). It orders the briefs left by `Priority:` (1 first, 2 when absent), then by number (the oldest issue), and takes the first.
2. **SPEC-0030 rule 3, how long a take is live.** The sentence "A take is live for 24 hours; after that it stays live only while a pull request by the same login, opened after the take, mentions the issue as `#n`" is replaced by: a take is live for `claim_hours` hours (4 by default) and after that only while a pull request has the line `Brief: #n` for the brief; a comment `released: <session>` ends the take of that session at once. The take that follows an expired one says `retakes`, and a take that reserves numbers says `reserves ADR-nnnn` (comma-separated, `REQ-nnn`, `SPEC-nnnn` and `ADR-nnnn`).
3. **SPEC-0030 rule 3, three more commands.** `session.py ids` prints one JSON line with the next free `req`, `spec` and `adr` numbers; `session.py demand` prints one JSON line `{"ready": r, "open": o, "max": m, "start": s}`; `session.py push-check` fetches the default branch, tries the merge of the head with it and exits 1 printing `conflict: <files>`, or exits 0 and prints nothing. None of them posts anything.
