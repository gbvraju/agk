# Proposed spec amendments 81 (SPEC-0032; REQ-039)

Date: 2026-10-26 (from `date -u`). Approved specs change only through a proposal like this one (principle 6). Applied by ADR-0145. The path: `docs/specs/0032-github-events-label-each-pr-people-approve-specs-a-red-branch-stops-work.md`. The number 81 and ADR-0145 were reserved for this build on #204 by the conductor (brief #231).

1. **SPEC-0032 rule 2, the checks that decide.** The router judges the checks of a head by the checks named in `required_checks` of `agk.toml` (a list of check names, default `["proof", "governance"]`): the latest run of each listed name and the latest status of each listed context decide `agk:ci-running`, `agk:ci-red` or green. A check that is not listed is ignored for the label. A listed check that has not reported keeps the pull request `agk:ci-running`. A listed check that is red stays red, whatever else is green. The router's own job is never judged.
2. **SPEC-0032 rule 7, the default branch.** `branch_state` and the name and link of the failing check in the red-branch brief use the same list, with one difference: a workflow such as `proof` runs on pull requests only, so the default branch waits only for the listed names that have a run or a status on its head. It is `pending` while one of those is not completed and when none of them has reported, `red` when one of them is red and `green` otherwise.
3. **SPEC-0032 residual of 2026-10-25.** "How a project lists them is decided at build (a)" is settled by `required_checks`; an invalid value is refused naming the setting and the router writes no label.
