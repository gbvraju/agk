# Proposed spec amendments 53 (SPEC-0030; REQ-037)

Date: 2026-10-24 (from `date -u`). Approved specs change only through a proposal like this one (principle 6). Applied by ADR-0104. The path: `docs/specs/0030-a-conductor-role-reviews-every-pull-request-posts-the-verdic.md`.

1. **SPEC-0030 rule 6, the pre-verdict steps.** The architect added seven steps to the brief of issue #163 (comment of 2026-10-24) for the conductor role: (1) CI first, (2) mergeable, (3) the reviewed sha is the head, (4) real paths only in `Final:` lines, (5) diagnose from the run, (6) collisions in flow mode, (7) a queue item a session cannot see. `.claude/agents/conductor.md` runs them in this order before every verdict. Step 5 is read as: the conductor reads the log of the failing job with `gh api` GET and names the step it shows; the reproduction with `AGK_BASE` set is the builder's, because the conductor runs no code of a pull request.
2. **SPEC-0030 rule 6, the guard.** `.claude/hooks/conductor_guard.py` judges `git` and `gh api` as `architect_guard.py` does (it imports those functions, so the two files are installed together) and allows nothing else: no script, no `make`, no `session.py` command.
3. **SPEC-0030 rule 11, the learnings of the architect on issue #163 are a later part.** `session.py verdict-ready --pr N` (steps 1 to 3 as a command), the `ci <success|failure> <sha>` end of `watch --pr`, `Brief: #n` and `Closes #n` in the pull-request body with the `check_pr_body.py` rules, the `doctor` finding for a missing `agk-brief` label, `next` skipping a brief whose pull request is open, and the At risk line for a stale brief are built after this part, each as its own pull request under the size rule.
