# Proposed spec amendments 84 (SPEC-0030, SPEC-0032, SPEC-0036; REQ-039)

Date: 2026-10-26 (from `date -u`). Approved specs change only through a proposal like this one (principle 6). Applied by ADR-0149. The paths: `docs/specs/0030-a-conductor-role-reviews-every-pull-request-posts-the-verdic.md`, `docs/specs/0032-github-events-label-each-pr-people-approve-specs-a-red-branch-stops-work.md`, `docs/specs/0036-whenever-a-pull-request-changes-state-the-project-publishes.md`.

1. **SPEC-0032 rule 8, what the router does not do.** "The router posts no comment" gains one exception: on a `Verdict:` comment of a listed author whose `Final:` line it cannot read (`common.verdict_problem`: a `Final:` line under a verdict that is not `fix list`, a line that does not match `Final: <path> [REQ-n] <old> -> <new>`, a requirements line without its id or the reverse, a `Final:` line in a fix list that also has numbered items) it posts one reply that begins `Correction needed:`, gives the message and names the comment, at most once for each verdict comment, with the permissions it has. It runs no agent and merges nothing; the label is decided as before.
2. **SPEC-0036 rule 5, the artifact.** "The router ... posts no comment" is read with the exception of item 1.
3. **SPEC-0030 rule 6, the guard.** `.claude/hooks/conductor_guard.py` also allows the conductor's comment `POST` of one `-F body=@<file>` for a regular file of a scratch directory, and denies a comment whose body starts with `Verdict:` and has a problem of item 1, with the router's message, whether the body comes from `-f` or from the file.
