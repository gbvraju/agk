# Proposed spec amendments 70 (SPEC-0028, SPEC-0008, SPEC-0031; REQ-035, REQ-038)

Date: 2026-10-25 (from `date -u`). Approved specs change only through a proposal like this one (principle 6). Applied by ADR-0134. The paths: `docs/specs/0028-in-flow-mode-a-kit-build-pull-request-does-not-bump-the-vers.md`, `docs/specs/0008-upgrade.md` and `docs/specs/0031-in-flow-mode-a-build-pull-request-adds-its-changelog-line-as.md`. The number 70 and ADR-0134 were reserved for this build on #212 by the conductor. It closes the two gaps the first release made in the flow-mode way (#214) found, on the verdicts on its head.

1. **SPEC-0028 rule 4, a release needs no ADR.** A pull request that is a release pull request, that is one that raises `version` in flow mode, changes only the files of the release (the five files of this rule and the deleted fragments) and passes `check_release.py`, needs no ADR for the protected files it must change (`agk.toml`, `kit/`, `.claude-plugin/`). `check_protected_changes.py` treats such a pull request as covered; one more file, or a release that fails its check, removes the exemption, and an ordinary protected change still needs its ADR. The exemption exists only where `check_release.py` does, which is the kit's own repository.
2. **SPEC-0008 rule 2 and SPEC-0031 rule 6, the row of a version ends at its release.** In flow mode the row of version V holds the digests at the first commit of the first-parent history whose tree states V, which is the commit that released V. Commits after it that still state V (the builds between two releases) belong to the next version's row, so that a file added since V is not read as one that V installed. The rule reads git only and needs no tag. Strict mode, where every change bumps the version, is as before, and so is every row before 0.54.0.
