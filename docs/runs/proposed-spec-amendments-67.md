# Proposed spec amendments 67 (SPEC-0030, SPEC-0034; REQ-041)

Date: 2026-10-25 (from `date -u`). Approved specs change only through a proposal like this one (principle 6). Applied by ADR-0130. The paths: `docs/specs/0030-a-conductor-role-reviews-every-pull-request-posts-the-verdic.md`, `docs/specs/0034-a-team-sets-how-many-builder-sessions-run-at-once-and-agk-ha.md`. The number 67 is the one the conductor reserved for brief #210.

1. **SPEC-0030 rule 2 and SPEC-0034 rule 12, a wait never goes silent.** Every wait of `session.py` (`watch --pr`, `--merged`, `--assign`) that cannot read GitHub for 5 polls in a row prints one line, `error: <what> cannot be read` (what is the pull request, the comments of a pull request or the comments of the conductor issue, by number), and exits 4; a single failed read is retried, a good read resets the count, and the first read of the comments of a wait is part of it. `watch --assign <id>` prints one line, `waiting on #<issue> since <id>`, when it starts (the id is the session's `Request:` comment, else the newest comment), so the log of a session shows what it waits for; the polls that do not end it write nothing. A failed first read no longer makes an old `Assign:` line look new.
2. **SPEC-0034 rule 11, a blocked session asks where the conductor reads.** `config/session-rules.md` rule 21: a session that is blocked for any reason posts `Question: Q-<id> <text>` on its pull request, or on its brief when it has none, and waits there; it never asks only in its own chat. Rule 22: a session pushes only the branch its runtime gives it and opens its pull request from that branch; a refused push for another branch is a block.
3. **SPEC-0030 rule 6, the conductor role file.** The conductor reads `Question:` comments on briefs as on pull requests, and answers from the rules when they answer it.
