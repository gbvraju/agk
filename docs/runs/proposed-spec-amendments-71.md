# Proposed spec amendments 71 (SPEC-0030, SPEC-0032; REQ-041)

Date: 2026-10-25 (from `date -u`). Approved specs change only through a proposal like this one (principle 6). Applied by ADR-0135. The paths: `docs/specs/0030-a-conductor-role-reviews-every-pull-request-posts-the-verdic.md`, `docs/specs/0032-github-events-label-each-pr-people-approve-specs-a-red-branch-stops-work.md`. The number 71 is the one the conductor reserved for build (b) of brief #210.

1. **SPEC-0030 rule 2, a verdict the watch would miss.** `watch --pr N` only ended on comments newer than the newest one it saw at start, so a verdict that landed between the push and the start of the watch, or a watch restarted later, was never seen and the session waited silently (seen on #209). At start it now also ends at once, printing the same `verdict <kind> <sha> (comment <id>)` line, when the latest verdict by a listed author names the current head and is newer than the last `Report:` comment of the pull request's author; an older verdict on a previous head never ends it, and the latest verdict decides. The last `Report:` stands for the push of the current head, because GitHub reports no push time for a head and a session posts a `Report:` after each push.
2. **SPEC-0032 rule 10, a correction the watch would miss.** At start the watch ends the same way, printing the `correction #<n> (comment <id>): <first line>` line, on a `Correction:` comment of a listed author, on the pull request or on the brief named by its `Brief: #<n>` line, that is newer than that `Report:`. The verdict comes before the correction.
3. **SPEC-0030 rule 2, `--since <comment id>`.** `watch --pr N --since ID` raises that floor to `ID` (a number; `--merged` and `--assign` take none). A session that has already acted on a verdict and only waits for CI or the merge restarts the watch with the id the line printed, so that the verdict is not reported again at each restart (`config/session-rules.md` rule 24).
