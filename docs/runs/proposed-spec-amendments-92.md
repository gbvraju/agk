# Proposed spec amendments 92 (SPEC-0008, SPEC-0006; REQ-039)

Date: 2026-10-26 (from `date -u`). Approved specs change only through a proposal like this one (principle 6). Applied by ADR-0164. The paths: `docs/specs/0008-upgrade.md` and `docs/specs/0006-doctor.md`. The number 92 and ADR-0164 were reserved for this build on #280 by the conductor (brief #269; verdict on ce7e674, item 3).

1. **SPEC-0008 rule 13, marked blocks, gains the extendable files of an init install.** The rule's title reads "Marked blocks (adopt) and extendable files (init and adopt)". A new paragraph: "`kit/manifest.json` lists under `extendable` the installed files a project is expected to extend, with their marker style; `.gitignore` (style `# >>> agk` / `# <<< agk`) is the only one. In an init install such a file is a marked block too: T is the text between the markers, N is the kit's block (`adopt.block_sources`), and the rules above apply. In either mode the lines outside the block are the project's: they are kept byte for byte, are never a conflict, and the file's line ends with `(project lines kept: n)` when n is not zero. An extendable file with no markers whose first lines hash as the installed release's kit lines (its whole-file row or its block row), followed only by other lines, is `replace (agk block added[; project lines kept: n])`: the block is written around the kit's present lines and the following lines are kept after it. Any other extendable file with no markers, project lines before the kit's included, is `conflict` (`differs from every released copy`)."
2. **SPEC-0008 rule 13, the sentence on files with no markers.** "A file with no markers, or an end marker without a start, is `conflict` (class `marked block`)" reads "... is `conflict` (class `marked block`), except an extendable file that the paragraph above migrates".
3. **SPEC-0006 rule 8, the kit comparison.** "and for `adopt` the marked blocks compared inside their markers only" reads "and for `adopt` the marked blocks, and for `init` the `extendable` files, compared inside their markers only (an `init` file of them without markers differs until the upgrade migrates it)". A new sentence: "When `vendored-differs` is `ok`, its message ends with `(<path>: project lines kept: n)` for each extendable file with n lines outside its block, n not zero." This is a message of an existing check, not a new check.
