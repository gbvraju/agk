# Proposed spec amendments 61 (SPEC-0021, SPEC-0030, SPEC-0032; REQ-039)

Date: 2026-10-25 (from `date -u`). Approved specs change only through a proposal like this one (principle 6). Applied by ADR-0122. The paths: `docs/specs/0021-when-a-fix-list-verdict-s-only-item-is-the-final-commit-and.md`, `docs/specs/0030-a-conductor-role-reviews-every-pull-request-posts-the-verdic.md`, `docs/specs/0032-github-events-label-each-pr-people-approve-specs-a-red-branch-stops-work.md`. The number 61 is the next one free on the default branch when this was written.

1. **SPEC-0021, the clearance rule for a spec.** A `Final:` line that sets a spec to `Approved` counts for `check_final_clearance.py` only when the pull request holds a first line `Approve: <sha> SPEC-<n>` (a hexadecimal sha of 7 to 40 characters, the spec's number) in a comment or in a review body by an account listed in `spec_approvers` of `config/reviewers.yaml` (SPEC-0032 rule 5). The check takes the reviews from `--reviews FILE` (the workflow writes them beside the comments); without the line it fails, naming rule 5 and the setting, never a spec or a handle. A review counts whatever its state, because the line is what approves. The `Final:` lines for ADRs are unchanged.
2. **SPEC-0030 rule 6, the conductor role file.** For an intake the conductor ends its verdict with `Approval: SPEC-<n> <path> Draft -> Approved, waiting for a person` and writes no `Final:` line for a spec until the person's `Approve:` line exists; it never writes `Approve:`. The `Final:` lines for ADRs stay as they are.
3. **SPEC-0032 rule 2, the order of the labels.** The router sets `agk:approve` when the latest verdict by a listed author that names the head has an `Approval:` line whose spec has no `Approve:` line of a listed person (comment or review), and that state comes before `agk:fix`: the order is `agk:conflict`, `agk:ci-running`, `agk:ci-red`, `agk:approve`, `agk:fix`, `agk:ready`, `agk:review` (the router had set `agk:fix` on #196, which also held an `Approval:` line). `agk:approve` also stays for a cleared or covered head whose pull request sets a spec `Approved` without such a line.
