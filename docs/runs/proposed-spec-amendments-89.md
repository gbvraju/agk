# Proposed spec amendments 89 (SPEC-0034; REQ-039)

Date: 2026-10-26 (from `date -u`). Approved specs change only through a proposal like this one (principle 6). Applied by ADR-0154. The path: `docs/specs/0034-a-team-sets-how-many-builder-sessions-run-at-once-and-agk-ha.md`. The number 89 and ADR-0154 were reserved for this build on #204 by the conductor (brief #247, build (b)). The command is `/agk:launch`, not `/agk:start`, by the ruling on Q-247-6: `/agk:start` is the vision command.

1. **SPEC-0034 rule 6, the rule that no session starts another.** "AGK ships no launcher and no session starts, stops or reviews another" reads: "AGK ships no launcher that runs on its own, and no session starts, stops or reviews another, except that a session starts other sessions when a person runs `/agk:launch` and confirms its plan." The contract of `session.py demand` stays as it is for a team's own launcher.
2. **SPEC-0034, new rule 16, `/agk:launch`.** A skill of the kit's plugin. It runs `session.py plan` and shows the plan in plain words; it asks the person once to confirm (only a plain yes counts; any other answer starts nothing); then it starts one session per planned slot through an adapter. In a runtime that offers one-time scheduled tasks (Claude's cloud) `(verify)` the adapter is one one-time scheduled task for each session, firing at once, with the standard builder prompt that names the session, the brief and `session.py claim`. Anywhere else the command prints one ready-to-paste prompt for each session, or calls the team's own command once for each session (`launch.py prompts --plan FILE --adapter COMMAND`, without a shell). It creates no recurring task, holds no credential and starts nothing later; running it again plans again from the current state. The prompt carries no title of a brief. Every runtime fact that cannot be confirmed is marked `(verify)`; the one measured fact is that a one-time scheduled task opened a working session within a minute (#204, `Report: launcher-test`).
3. **Tests (rule 14).** The prompts, the refusal of a plan that is not a plan, the adapter called once per session against a stub, a failing adapter that stops the run, no shell, the skill's order (plan, confirm, prompts) and its words, and the guide.
