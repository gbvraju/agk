# Proposed spec amendments 55 (SPEC-0021, SPEC-0009, SPEC-0022, SPEC-0026; REQ-037)

Date: 2026-10-24 (from `date -u`). Approved specs change only through a proposal like this one (principle 6). Applied by ADR-0109. The paths: `docs/specs/0021-when-a-fix-list-verdict-s-only-item-is-the-final-commit-and.md`, `docs/specs/0009-facts.md`, `docs/specs/0022-the-weekly-product-report-also-publishes-the-sections-it-com.md`, `docs/specs/0026-each-section-of-the-weekly-report-each-grouped-item-in-it-an.md`.

1. **SPEC-0021 rule 4, a late clearance fails.** `check_final_clearance.py` fails, naming `rule 7` and never a value, when the latest verdict by a listed author is a covered fix list and the head is two or more commits past the reviewed sha. The commits are counted on the first-parent line, so a merge of the base branch is one commit. A reviewed sha that is not in the history of the head says nothing and passes, as an uncovered fix list, a cleared verdict and no verdict do. The head at the reviewed sha and the one commit after it are checked as before (SPEC-0030 rule 7).
2. **SPEC-0009, the facts of an open pull request.** The pull-request record carries `head_cleared` for an open pull request as for a merged one: `yes` when a cleared verdict or the covered final commit names the head, `no` when the verdicts were read and none clears it (no verdict yet is `no` for an open pull request), `unknown` when the verdicts could not be read. A closed pull request that was not merged carries none. `facts.json` keeps schema number 1 (SPEC-0030 rule 8).
3. **SPEC-0022 and SPEC-0026, the group `ready`.** The decisions section of the report gains the group `ready` ("Ready to merge"), the first group, with the item kind `pull-request-ready` (`number`, `title`) for each open pull request whose `head_cleared` is `yes`, linked to it. `report.json` takes schema number 4 and `kit/report-schema.json` requires it. The counts of SPEC-0026 include the group. An open pull request whose verdicts cannot be read is not listed and adds one `unknown` item to the group ("the clearance of N open pull requests"), which gives the group the count `unknown`; the pull-request group keeps its own `unknown` item for the same pull requests (Q-K4-269). The markdown prints `PR #<n> "<title>" is ready to merge`, linked, under Needs you; no other line of the report changes.
