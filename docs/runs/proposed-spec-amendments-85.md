# Proposed spec amendments 85 (SPEC-0032; REQ-039)

Date: 2026-10-26 (from `date -u`). Approved specs change only through a proposal like this one (principle 6). Applied by ADR-0150. The path: `docs/specs/0032-github-events-label-each-pr-people-approve-specs-a-red-branch-stops-work.md`. The number 85 and ADR-0150 were reserved for this build on #204 by the conductor (brief #242).

1. **SPEC-0032 rule 5, an approval an agent posted.** `agk.toml` gains `agent_apps`, a list of GitHub App slugs (default `["claude"]`; an invalid value is refused naming the setting). A comment whose `performed_via_github_app.slug` is in `agent_apps` never counts as a person's approval, with one account or several: the rule is the same everywhere a person's approval is counted (the router, `check_specs.py` and `check_final_clearance.py`), and a listed approver's login is still required. A review record shows no app, so while `agent_apps` is not empty a review never counts as a person's approval (ruling on Q-242-1); with `agent_apps = []` reviews count as before.
2. **SPEC-0032 rule 5, visible.** For an `Approve:` comment of a listed approver that was posted through a listed app, and for a review of a listed approver that would have counted, the router posts one reply that begins `Correction needed:` (at most once for each comment or review): for a comment, that an approval posted through an agent's app does not count and the person posts it themselves; for a review, that the person posts `Approve: SPEC-<n>` as a comment from their own account. No label depends on the reply.
3. **Guide.** The security guide and the getting-started guide state the limit: the field exists when an agent posts through an app, as cloud sessions do; a session on a person's own machine that uses that person's `gh` login posts with no field and looks like the person. The first-line markers and the session names keep roles readable and are not proof.
