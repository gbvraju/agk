# Proposed spec amendments 88 (SPEC-0034; REQ-039)

Date: 2026-10-26 (from `date -u`). Approved specs change only through a proposal like this one (principle 6). Applied by ADR-0153. The path: `docs/specs/0034-a-team-sets-how-many-builder-sessions-run-at-once-and-agk-ha.md`. The number 88 and ADR-0153 were reserved for this build on #204 by the conductor (brief #247, build (a)). Build (b), `/agk:start` and its adapter, has its own amendment.

1. **SPEC-0034, new rule 15, the plan.** `session.py plan` prints a plan of which sessions take which briefs and why the others wait, in plain words, and with `--json` the same plan as data. It posts nothing, runs no model and starts nothing. Its inputs are the ready briefs (open, not taken, `Depends-on` merged and not stale; a `taken:` claim counts even with no pull request yet), their `Touches:`, the open builder pull requests with their labels and files, `max_builders`, and three new settings of the `[flow]` table, each a whole number of 1 or more: `reviews_in_flight` (the conductor's review capacity, default 3), `merge_hours` (default 1) and `stale_commits` (default 20).
2. **Waves.** A brief whose `Touches:` overlap running work (a taken brief, the files of an open builder pull request) waits for it. Two ready briefs whose `Touches:` overlap never start in the same wave: the later by priority and then number waits and is named with the brief it waits for. The shared mechanical files of rule 7a never make two briefs overlap.
3. **Capacity.** The sessions to start are the smallest of the ready non-overlapping briefs, `max_builders` less the running builders (open builder pull requests and claims with no pull request yet) and `reviews_in_flight` less the pull requests labelled `agk:review`.
4. **The merge queue, measured.** The merge rate is the number of pull requests merged in the last 14 days divided by the active hours: hour-long buckets, counted back from now, that hold at least one merge. While the pull requests labelled `agk:ready` exceed `merge_hours` times the rate, the plan starts no new session and says so in one line; it never stops a running session. With no merge in the last 14 days the rate is unknown, the limit does not apply and the plan says so.
5. **The safe merge set.** The plan lists the `agk:ready` pull requests that share no changed file (the shared mechanical files aside) as one set that can be merged together. They are ordered by the waiting briefs each one unblocks, then by the priority of its brief, then by age; those that change a path of `config/protected-paths.txt` are marked. A pull request that shares a file with an earlier one of the set is listed after it, naming the file.
6. **Drift.** A ready pull request more than `stale_commits` behind the default branch (the `behind_by` of one `compare` read), and a pull request labelled `agk:conflict`, are listed for their builder to update, not for the person to merge. A `compare` that cannot be read is listed as unknown, never as zero.
7. **Stale briefs.** A brief with the line `Status: stale` or the label `agk-stale` is skipped by `plan` and by `next`, with the reason `stale`.
8. **The pipeline document.** SPEC-0036 rule 2 lists exactly the fields of schema 1, so an optional field for the safe merge set needs a change of that schema: it is a follow-up, not part of this build.
