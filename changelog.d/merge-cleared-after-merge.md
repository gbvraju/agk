- `merge_cleared.py` now finishes what follows a merge: it merges only while one record issue is open (the local-mode record issue, else the one `agk-auto-merge` issue), posts one `Auto merge: #<n> <merge sha> <UTC time> <verdict link>` line there, runs `make governance` on the merged default branch in a temporary worktree under the heavy lock with no token in its environment, and, when that run is red, opens the router's red-branch issue, prints `merge-cleared: stopped: default branch red after #<n>` and exits 1, which holds every later merge; the wait for the heavy lock is bounded by `[flow] after_merge_timeout` (minutes, 30 by default), and a run cut off after the merge by an error, an interrupt or a termination opens the red-branch issue too (brief #551, ADR-0273 Proposed)
